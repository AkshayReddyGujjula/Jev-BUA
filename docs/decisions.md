# Deliberate decisions

Short records for choices a future agent must not "fix" back. Each one is a
deliberate deviation from the obvious alternative.

## ADR-001 — Human checkpoints stop a slice; they do not serialize a task

A delegated task owns its `Agent`, its browser and its tab inside one MCP server
process. `browser_task` runs a bounded slice and returns either a terminal
result or a checkpoint (`needs_human`, `paused`). `browser_task_resume`
continues the same object after a fresh observation, so the login performed in
Chrome survives. A server restart invalidates the task id; the caller starts a
new task instead. Tasks are single-use and process-nonced.

Why not a persisted task state machine: the safety model depends on a live
browser, a consumed-before-mutation decision, and a freshness check; serializing
half of that across processes would weaken all three for little gain.

## ADR-002 — The anti-loop deadline measures an active segment

The five-second no-progress deadline and the eight-round backstop still bound
every active segment, but a human wait rebases the clock (`started_at`,
`progress_at`, `progress_wall_at`, `stall_rounds`). Without this, any login
checkpoint would end the next tick as `stalled`. A page that stops responding
*during* active work still terminates within the usual window.

## ADR-002a — Model waits are not page stalls (2026-09-23)

The five-second deadline measures browser-side time only: every model wait
(decision, text helper, failure classifier, supervisor) is credited back to
`progress_at`. On 2026-09-23 Jev's median decision latency moved from 0.3 s to
1.8 s for about an hour; under the old clock two slow decisions on a responsive
page ended runs as `stalled`, which is a false diagnosis of the page. Model
waits stay bounded by each call's own timeout, by the eight-round cap, and by a
wall-clock backstop (`progress_wall_at`, `JEV_STALL_HARD_SECONDS`, default 20 s)
that nothing is credited against. A model call that cannot finish inside the
backstop is not started, and observations cap their settle wait at the earlier
of the two deadlines.

## ADR-007 — The supervisor is on demand, telemetry-triggered, and narrow (2026-09-23)

A vision LLM costs 1.5-2.5 s per call against Jev's ~0.3 s, so it never sits on the
fast path and never watches periodically. Code-owned checks decide when it is consulted
(`no_progress_deadline`, `repeated_no_progress_rounds`, `dead_streak`, `model_blocked`)
and the trigger is sent by name: naming the failing check is what made LLM repair work
in the literature (arXiv 2608.02464). Its authority is a hint, one observed element, or
a terminal signal - never coordinates. It replaced the screenshot planner, which could
click coordinates and therefore had to be disabled for delegated tasks; a supervisor
action is an ordinary decision and passes the same freshness check and approval.

## ADR-008 — Reversible actions are not confidence-gated by default (2026-09-23)

The v2 gate refused any mutation below 0.5 confidence. Jev's confidence measures how
concentrated its choice is, and a split page (Search button vs. the search box) reads
low while the top choice is still right: on the local trap form a Search click at 0.47
was refused twice and the run looped instead of submitting. Refusing a reversible action
buys no safety - it can be undone - and costs a re-observe, a second decision, and
often a loop. The original loop always executed the argmax. Reversible actions do so
again; the 0.9 floor for commits (clicks Jev marks irreversible) is unchanged, and
`JEV_GATE_REVERSIBLE` restores a reversible floor for anyone who wants one.

## ADR-009 — Goal literals and generated values are not masked (2026-09-23)

7fa3ced masked every typed value, and every caller-supplied value, in Chrome's snapshot
before Jev saw it. That hid the evidence of success from the decision model: on the local
trap form the results page read "Results for [private]", Jev could not tell its search
had worked, and it chose BACK at goal_done 0.07 in six of six runs; on Google Flights a
typed "Zurich" also masked every autocomplete option that echoed it. Masking protects
nothing when the value is a goal literal (the goal already carries it to the model) or
was generated by the text model from context the provider already saw. Masked now: values
from the local profile and learned memory, supplied values that do not appear in the goal,
and anything under a sensitive label. Measured after the fix: the same form finishes in
1.5-2.4 s with a 0.95-confidence Search click and a direct DONE.

## ADR-010 — The text helper stays hosted; local 2-4 GB models measured slower (2026-09-23)

`scripts/benchmark_text_helper.py` gives every provider the identical TEXT_VALUE prompt and
field_context over 15 labelled cases (profile facts, goal values, three fields whose only
correct answer is null, one free-text answer), two repeats, full and slim context. On this
laptop (Core Ultra 7 258V, 32 GB, Ollama 0.32.15 CPU-only - no Arc offload):

| provider | warm median | p90 | cold load | accuracy | invented values |
| --- | --- | --- | --- | --- | --- |
| deepseek-v4.1-flash, hosted, reasoning off | 1.6-1.7 s | 2.4-2.7 s | - | 93-97% | 0 |
| qwen3.5:2b-q4_K_M | 3.9-4.0 s | 7-22 s | 11-25 s | 73-80% | 4 |
| granite4.2:3b | 2.5-5.0 s | 9-39 s | 17-57 s | 87% | 2-3 |
| qwen3.5:4b | 3.9-6.8 s | 11-37 s | 17-42 s | 80-100% | 0 |

No local model was faster, the two smaller ones invented a National Insurance number and
a salary, and CPU inference starved the browser daemon (a CDP call timed out during the
run). The hosted helper stays; its latency is to be hidden by prefetching values in
parallel with Jev's decision rather than by a local model.

## ADR-011 — Field values are drafted in parallel with the decision (2026-09-23)

The text helper (~1.3 s) sat on the critical path twice per Flights run. Now one batch
call (TEXT_VALUES) drafts every fillable field that is not sensitive, supplied, or in mode
memory, launched when `predict` starts, so it overlaps Jev's decision. A draft is used only
under the identical goal and only for a field it saw; a page with a field no draft has seen
gets a new draft, and a finished older draft is used at once instead of waiting on a newer
one. Validation is whole-batch: an unrequested key or a non-string value voids the batch
and the field falls back to the single-field call. Keys are matched on normalized labels
(Google's "Where to? " carries a trailing space) and a bare mapping is accepted as well
as `{"values": ...}` (measured: the model drops the wrapper on some real pages).
Measured on Flights (background tab, 4 runs): both text waits 0 ms, 10.5-12.8 s verified
4/4, 3 batch calls per run instead of 2 single calls.

## ADR-012 — Review hardening of the supervisor and the ungated clicks (2026-09-23)

An independent adversarial review (OpenCode, deepseek-v4.1-flash) of ADR-007..011 found,
and this fixes: the supervisor could press Enter (key actions are not gated) - key actions
are no longer supervisor-executable; it judged a click with Jev's *previous* irreversible
reading, possibly from another page - the reading now counts only when its fingerprint is
the current page's, and a missing one is treated as possibly irreversible; a link labelled
"Unsubscribe" or "Deactivate account" escaped both the supervisor's commit check and the
delegation boundary - the shared commit/security vocabulary now lives in gates.py, gains
`deactivate` and `unsubscribe`, and is checked before the role exemption (toggles excepted);
in delegated tasks a supervisor action is always re-entered as a hint so the approval
boundary judges it with a fresh reading. With reversible actions ungated (ADR-008), a click
whose own label names a commit keeps a 0.5 floor (`JEV_GATE_LABELLED`) even when the page-
level `irreversible` noul reads low or is malformed - a "Delete" at 0.4 is refused, a
"Search" at 0.4 is not. `passphrase`, `passkey` and `token` joined the sensitive labels, and
supervision records are redacted like every other result field.

## ADR-013 — A slow decision is hedged once (2026-09-24)

Over 533 live Jev decisions in this week's evidence the answer arrived in a median 286 ms,
p99 760 ms, max 929 ms. The failures were a separate population: requests that hung to the
whole 3 s budget, and two in a row ended a Flights run `blocked`. The retry already in the
loop only fires after that full 3 s. A decision is read-only, so when none has answered by
`JEV_DECIDE_HEDGE` (1.0 s, above every observed success) one identical request goes out on
its own HTTP/2 client - a stalled pooled connection would stall a hedge sharing it - and the
first valid answer wins, inside the same total budget. Evidence records `hedged`
(`primary`/`hedge`). Two verified Flights runs afterwards (12.4 s, 12.6 s) fired no hedge, so
a healthy provider pays nothing. Only the decision call is hedged; nothing that mutates, and
not the text helper, whose single-field answers are not idempotent in content.

## ADR-014 — Decision connections stay open and open early (2026-09-24)

A new TLS + HTTP/2 connection to TypeSafe costs ~325 ms (499 ms cold vs 173 ms warm, same
request). httpx closes an idle pooled connection after 5 s by default, so any decision more
than 5 s after the previous one paid it again, and a fresh process always paid it inside its
first decision (first-decision tail 780-950 ms against a 287 ms median). TypeSafe kept idle
connections for 90 s+ when probed, so both decision clients now keep them for
`JEV_KEEPALIVE_SECONDS` (120), and `Agent()` opens both with an unauthenticated HEAD while the
tab opens (skipped without a key, so tests stay offline). Matched live Flights runs, 14
decisions each: 12.4-12.6 s before, 10.4-11.7 s after (3/3 verified); decision time 6.4-6.8 s
to 4.6-5.6 s; first decision 839-951 ms to 329-415 ms.

## ADR-003 — No secret store; the profile holds non-secret data

`~/.jev-ultrafast/profile/` stores identity fields and site usernames as
plaintext. Password, one-time-code, recovery and payment labels are refused even
when present in the JSON, and the human types them into Chrome. A Windows DPAPI
vault is a separate later feature with its own threat model. This is data
minimization, not confidentiality: a site necessarily receives anything typed
into it.

## ADR-004 — Approval is caller-mediated

`approve_action=true` is a promise by the MCP caller that a human approved the
exact proposed action. The server cannot authenticate who answered. Consequences:
use a trusted orchestrator; the manual demo asks in the terminal; label and risk
heuristics catch common committal controls but can miss an obscure or unlabeled
one, so sensitive work should be inspected live.

## ADR-005 — Jev routing is shadow-first and code-gated

`JEV_ROUTER=enforce` can only take effect with at least six active task classes
and at least thirty human-labelled tasks for the current candidate set, with
coverage, accuracy and per-class precision floors. `new_class` always goes to
the text classifier because Jev cannot generate trustworthy metadata. Rationale:
the calibration data for this taxonomy does not exist yet, and an uncalibrated
router would confidently misroute.

## ADR-006 — One delegated task per MCP server instance

A second concurrent task is refused. Parallel work needs separate server
instances with their own `JEV_MCP_BU_NAME`. Multiple tasks in one process would
reintroduce the cross-tab ownership races the repo has already paid for.

## ADR-007 — Verification requires a live readback

`outcome=verified` needs an `expect` readback performed after the task, in one
JavaScript evaluation, so route changes cannot combine facts from two page
states. If the readback fails, the outcome is `unknown`; a `done` choice is never
proof. A harvest count alone cannot verify a page.
